# Entrega 2 - Gestão do Pug Quest no GitHub

## Objetivo

Esta etapa transfere o planejamento elaborado na Entrega 1 para uma ferramenta real de gestão de projetos. O GitHub concentra o repositório, as Issues e o histórico de documentação, enquanto o GitHub Projects apresenta o trabalho em um quadro Kanban.

## Estrutura criada

- Repositório privado do Pug Quest para a disciplina
- GitHub Project chamado Pug Quest - Gestão com Scrum
- Quadro Kanban com Backlog, Ready, In progress, In review e Done
- Dezesseis Issues correspondentes ao Product Backlog
- Atribuição das Issues ao responsável pelo projeto
- Critérios de aceite, checklists, prioridades, estimativas, Sprints e versões em cada Issue
- Visualizações adicionais de Backlog, Priority board, Team items, Roadmap e My items

## Relação com a Entrega 1

Os itens PUG-01 a PUG-16 mantêm os mesmos identificadores, prioridades e Story Points definidos no planejamento. Essa correspondência evita duplicidade entre o documento acadêmico e a ferramenta de acompanhamento.

## Situação registrada

| Estado | Conteúdo |
| --- | --- |
| In progress | PUG-01 - Configuração do repositório, do Project e das evidências |
| Ready | PUG-02 - Estrutura do frontend, backend e ambiente local |
| Backlog | PUG-03 a PUG-16 - Funcionalidades, qualidade e entrega |
| In review | Reservado aos itens que aguardarem validação |
| Done | Reservado aos itens que atenderem à Definição de Pronto |

## Etapas do projeto

1. Planejamento e configuração da gestão
2. Preparação da fundação local
3. Implementação da gestão de campanhas
4. Desenvolvimento dos conteúdos narrativos
5. Construção do campo de batalha
6. Testes, documentação, implantação e avaliação

## Versões

O planejamento trabalha com cinco versões: v0.1.0, v0.2.0, v0.3.0, v0.4.0 e v1.0.0. Cada versão reúne um incremento verificável e mantém a relação com as Sprints correspondentes.
