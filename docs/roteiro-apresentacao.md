# Roteiro de apresentação da Entrega 2

## Abertura

Boa noite. Nesta segunda entrega, eu transferi o planejamento do Pug Quest para o GitHub, utilizando uma ferramenta real de gestão de projetos. O objetivo foi transformar o documento da primeira etapa em um ambiente rastreável, com tarefas, estados, Sprints e versões.

## Repositório

Eu criei um repositório privado específico para a disciplina. Ele concentra as Issues e a documentação do projeto sem alterar o repositório funcional do TCC. O README apresenta o objetivo da entrega, as tecnologias previstas e a organização do trabalho.

## GitHub Project

O GitHub Project funciona como um quadro semelhante ao Jira. Ele utiliza as colunas Backlog, Ready, In progress, In review e Done. Essa divisão permite visualizar o que ainda precisa ser detalhado, o que está pronto para começar, o que está em execução e o que já passou por validação.

## Product Backlog

O backlog possui dezesseis Issues, numeradas de PUG-01 a PUG-16. Cada Issue contém descrição, critérios de aceite, tarefas menores, prioridade, Story Points, Sprint, versão, dependências e evidências esperadas.

## Situação atual

A configuração do ambiente de gestão aparece em In progress. A preparação da arquitetura local está em Ready. Os demais itens permanecem no Backlog porque ainda dependem das Sprints futuras. Essa organização evita apresentar como concluído algo que ainda não possui evidência.

## Sprints e versões

O trabalho foi dividido em seis Sprints, da Sprint 0 à Sprint 5. As versões começam na v0.1.0, voltada à fundação local, e evoluem até a v1.0.0, planejada para implantação e avaliação com usuários.

## Implementação local

A solução foi planejada com React e Next.js no frontend, Node.js no backend e Supabase no banco de dados. O repositório registra a estrutura esperada, os pré-requisitos e a sequência necessária para iniciar os serviços localmente.

## Encerramento

Com essa entrega, o planejamento deixou de existir apenas no documento e passou a ser acompanhado em uma ferramenta real. O GitHub permite relacionar requisitos, tarefas, futuras alterações de código, testes e versões ao longo da evolução do Pug Quest.
